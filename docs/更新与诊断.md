# 交付与安全诊断

按项目所有者最终要求，正式版仅交付新版 Windows 整合包、源码和 SHA256，不提供旧版一键升级或候选频道衔接。已有私密 data 不应删除或被干净包覆盖。历史更新器源码与测试保留供开发参考，不作为正式用户入口。

## 群聊初始化顺序

1. 开启插件后，先在 QQ 群发送 `/help` 和 `/sid` 检查 AstrBot 原生功能。
2. 发送 `/身份`，无需群白名单或模型配置，就能返回真实群 ID 和发送者 ID；此操作不调用模型。若别的插件也注册了“身份”，使用 `/毒舌身份`。
3. 将你自己的发送者 ID 加入本机 AstrBot 管理员，将真实群 ID 加入插件 `allowed_groups`，保存并重载。原生 QQ 官方机器人 ID 是 OpenID，不一定是手机 QQ 显示的群号。
4. 在原生面板创建官方 DeepSeek 模型提供者，Key 只填面板，插件 `provider_id` 选择模型提供者实例：例如 `deepseek/deepseek-flash`，不是提供商源 `deepseek`。
5. 管理员发送 `/启用群聊 已告知群友`，再发送 `/帮助`、`/状态` 和 `/吐槽 为什么大学早八这么折磨人`。明确请求有冷却，测试时不要连续刷多条模型命令。
6. 主动发言默认关闭。群成员知情同意后先 `/上下文 开启 已告知群友`，再单独 `/主动 自然` 或 `/主动 活跃`；至少两位成员讨论，观察频率限制。它不会每条必回。

原生 `/help`、`/sid` 以及其他已经匹配的插件命令优先交回 AstrBot；插件不会拿未知 `/指令` 请求模型。未授权群的普通和 @ 消息不进入自研上下文、不调用模型，也不终止其他插件。该保护不替代你在其他插件中自行配置其模型权限。

## 无回复时的安全诊断

双击 **安全诊断.bat**，输入 `1` 开启，然后停止并重新启动机器人，在 QQ 群复现一次。再次双击，输入 `2` 查看计数和安全错误类别。完成后输入 `3` 关闭。诊断最多一小时自动失效，默认关闭，不需要改 Python 源码。

记录文件 `data/safe-diagnostics.jsonl` 只包含时间、固定阶段代码、短期随机事件编号和固定错误类别；没有聊天正文、Key、QQ Secret、群 ID 或成员 ID。它不是框架原始日志，不要分享整个 data 目录。

| 观察结果 | 含义和下一步 |
|---|---|
| 没有 `adapter.group.received` | 本次窗口未观察到 QQ 群事件。先确认启用后已重启、适配器与 QQ 权限；不能单凭“没有记录”断言平台未投递 |
| 有适配器记录，没有 `pipeline.begin` | 事件已交给框架，但没有进入调度；检查框架服务状态 |
| `pipeline.no_plugin` | 已进入框架但没有进入自研处理器；检查插件启用、会话插件设置和框架前置白名单/限流 |
| `plugin.pass.command` | 原生或其他插件命令正常放行，不属于自研消息 |
| `plugin.ignore.unlisted` / `plugin.ignore.policy` | 允许群、授权、上下文、去重或主动策略选择忽略，不代表适配器故障 |
| `plugin.reply.ready` 后有 `send.failed` / `plugin.reply.failed` | 已生成回复，但 QQ 发送失败；检查主动/回复权限和 QQ 审核限制 |
| `model.failed` + `http_429` / `timeout` / `network` | 模型限流、超时或网络故障。已退避；不会自动再付费请求 |

正常隐私模式仍显示处理阶段和错误类别，正文及异常原文始终隐藏。具体 QQ 服务端返回的敏感响应和身份不会直接公开。
