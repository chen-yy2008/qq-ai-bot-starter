# 候选更新和安全诊断

当前渠道为 `v1.0.0-rc.1` 公开候选版，不是正式 v1.0.0。普通用户无需 GitHub 登录。更新入口不会安装新的 Python 或重新安装 AstrBot。

## 已安装的用户

双击最外层 **检查并更新.bat**，查看候选版本、说明和将修改的文件清单，输入 `Y` 确认。更新器通过本项目 GitHub Releases 的匿名 HTTPS 下载，验证 ZIP SHA256、大小和逐文件清单；API 可用时额外核对 GitHub 资产摘要。适用框架必须为 AstrBot 4.29.0。

若 GitHub 匿名 API 配额耗尽（403/429），或 API 临时不可达，会明确提示并改用同一仓库、同一公开候选 Release 的固定 HTTPS 清单。TLS 证书、来源、ZIP SHA256、大小、版本和逐文件校验仍全部保留；不需要登录或填写令牌。两个公开入口都不可达时才报网络失败，不会开始覆盖。

下载或校验失败时不会停止正在运行的机器人。校验通过后只备份清单里的程序文件，请求本目录启动器停止服务，然后安装并重新启动。若旧版启动窗口不能被安全识别，会要求你在原窗口按 Ctrl+C 后重试，绝不按进程名称强杀 Python。

更新完成会显示“候选更新成功，后台已就绪”。这不代表真实 QQ 或 DeepSeek 测试已经通过。失败时会显示恢复结果；不能完整恢复时会停止后续操作并明确提示需要人工处理，不会显示成功。

备份位于本机 `data/update-backups/日期-随机编号/`。`transaction.json` 记录逻辑文件位置、原文件摘要和恢复状态；对应的 `.original` 是原程序文件。不要删除未完成更新的备份。进程被强制结束、断电等无法捕获的中断会留下未完成状态；下次更新会拒绝继续覆盖，请保留备份并联系维护者恢复。

## 保留哪些数据

更新器使用固定允许文件清单，不覆盖整个 `data/plugins`。面板配置、Key、QQ AppID/AppSecret、管理员、插件 allowed_groups、人格 JSON、SQLite 数据库、其他插件都不在更新清单内。框架源码与 Python 依赖也不在清单内。

新旧目录都支持：新版的内部程序在 `程序文件`，旧版在解压根目录。请使用同一目录中的启动、停止和更新入口，不要同时运行两个副本。不要删除 data 来解决登录、授权或无回复问题。

## 群聊初始化顺序

1. 开启插件后，先在 QQ 群发送 `/help` 和 `/sid` 检查 AstrBot 原生功能。
2. 发送 `/身份`，无需群白名单或模型配置，就能返回真实群 ID 和发送者 ID；此操作不调用模型。若别的插件也注册了“身份”，使用 `/毒舌身份`。
3. 将你自己的发送者 ID 加入本机 AstrBot 管理员，将真实群 ID 加入插件 `allowed_groups`，保存并重载。原生 QQ 官方机器人 ID 是 OpenID，不一定是手机 QQ 显示的群号。
4. 在原生面板创建官方 DeepSeek 模型提供者，Key 只填面板，插件 `provider_id` 填该提供者的 ID。
5. 管理员发送 `/启用群聊 已告知群友`，再发送 `/帮助`、`/状态` 和 `/吐槽 为什么大学早八这么折磨人`。明确请求有冷却，测试时不要连续刷多条模型命令。
6. 主动发言默认关闭。群成员知情后分别开启短期上下文和主动档位；至少两位成员讨论，观察频率限制。它不会每条必回。

原生 `/help`、`/sid` 以及其他已经匹配的插件命令优先交回 AstrBot；插件不会拿未知 `/指令` 请求模型。未授权群的普通和 @ 消息不进入自研上下文、不调用模型，也不终止其他插件。该保护不替代你在其他插件中自行配置其模型权限。

## 无回复时的安全诊断

双击 **安全诊断.bat**，输入 `1` 开启，然后停止并重新启动机器人，在 QQ 群复现一次。再次双击，输入 `2` 查看计数和安全错误类别。完成后输入 `3` 关闭。诊断最多一小时自动失效，默认关闭，不需要改 Python 源码。

记录文件 `data/safe-diagnostics.jsonl` 只包含时间、固定阶段代码、短期随机事件编号和固定错误类别；没有聊天正文、Key、QQ Secret、群 ID 或成员 ID。它不是框架原始日志，不要分享整个 data 目录。

| 观察结果 | 含义和下一步 |
|---|---|
| 没有 `adapter.group.received` | 本次窗口未观察到 QQ 群事件。先确认启用后已重启、适配器与 QQ 权限；不能单凭“没有记录”断言平台未投递 |
| 有适配器记录，没有 `pipeline.begin` | 事件已交给框架，但没有进入调度；检查框架服务状态 |
| `pipeline.no_plugin` | 已进入框架但没有进入自研处理器；检查插件启用、会话插件设置和框架前置白名单/限流 |
| `plugin.pass.command` | 原生或其他插件命令正常放行，不属于自研消息 |
| `plugin.ignore.unlisted` / `plugin.ignore.policy` | 允许群、授权、上下文、去重或主动策略选择忽略，不代表适配器故障 |
| `plugin.reply.ready` 后有 `send.failed` / `plugin.reply.failed` | 已生成回复，但 QQ 发送失败；检查主动/回复权限和 QQ 审核限制 |
| `model.failed` + `http_429` / `timeout` / `network` | 模型限流、超时或网络故障。已退避；不会自动再付费请求 |

正常隐私模式仍显示处理阶段和错误类别，正文及异常原文始终隐藏。具体 QQ 服务端返回的敏感响应和身份不会直接公开。
