# 开发和许可证说明

本项目复用原版 AstrBot `v4.29.0` 的平台接入、原生 WebUI、提供者配置及官方 QQ SDK；只增加群聊策略插件、四套可编辑人格、本地检查和 Windows 引导。没有非官方 QQ 协议、额外服务器、远程命令工具或自动后续开发。

插件不调用通用 Agent，不传递工具。v4.29.0 的 `text_chat()` 忽略额外的 `max_tokens` 并有外层重试，所以本插件复用已配置的 AsyncOpenAI 客户端，通过隔离的 `with_options(max_retries=0, timeout=20)` 发送一次兼容请求，明确限制 `max_tokens=256` 并关闭思考模式。模型 ID 从框架模型配置读取，Key 不进入本插件文件。只允许官方 `https://api.deepseek.com` 客户端地址。

`plugin/core.py` 用 SQLite 保存每群设置、哈希化成员偏好、手动记忆、每日预算。短期消息仅在内存中保存，最多每群 24 条、每条 400 字、TTL 600 秒，不在重启后恢复。群间通过 AstrBot 的完整会话来源隔离。每群记忆最多 100 条、每条 300 字；删除启用 SQLite secure_delete。每实例最多处理允许列表中的前 128 个群。退出记忆只会自动删除本人创建的条目，管理员仍有责任处理他人误录的信息。

所有模型请求先按 UTF-8 文本字节数、最多 1024 图片 Token 和输出限额做保守预留，在任何 await 之前写入每群与全局预算；返回 usage 时替换预留。失败不返还不确定消费；显示估算标记和配置单价，不虚构精确账单。没有自动付费重试；错误使新请求进入上限 300 秒的指数退避。全局并发最多 4，群内只允许一个进行中的请求。静音、人格/隐私修改会使进行中的旧输出失效。

图片使用 aiohttp 校验并固定 DNS 解析结果，拒绝所有非公网地址、凭据、非 HTTPS、非 443 端口和重定向；限制下载体积后由 Pillow 转换第一帧为 JPEG，再以内联数据送模型。不会把事件里的本地路径当成可读文件。群聊图片默认不触发主动模型请求。

开发机安装 Python 3.12 后，使用固定 uv 0.9.5 和 `packaging/requirements-win.lock` 安装依赖。离线策略测试执行 `python -m unittest discover -s tests -v`；真实框架集成测试还需要 `ASTRBOT_SOURCE` 指向官方固定源码。运行 Windows asyncio 测试的环境必须允许本机回环 socket，受限沙箱可能在事件循环初始化处阻塞。

Windows 密码模块为纯标准库，不导入 AstrBot。原因是导入 `astrbot.core.config.default` 也会先执行父包的 `AstrBotConfig()`，旧版因此在首次分支之前生成未知随机密码。现在先用 WinForms 窗口确认本机密码，再原子提交兼容上游的 PBKDF2-SHA256（600,000 轮）和旧版哈希，之后才导入框架；清除继承的初始化/重置密码环境变量。窗口与 Python 仅通过匿名管道在本机内存中传递密码，不写入命令行、环境变量或日志。已有安装没有本机设置凭据时也会弹窗，测试生成配置不能作为初始化证明。

重置只更新 dashboard 的 password、pbkdf2_password、password_storage_upgraded、password_change_required、jwt_secret；缺失用户名时补默认 astrbot，已有用户名、二步验证及所有非认证内容保留。相同安装使用文件锁阻止运行中重置，再检查后台端口。配置在同目录临时文件中完整写入并 fsync，确认旧内容未发生变化后通过 os.replace 提交；此前任何异常、取消或验证失败均不覆盖原文件。初始化证明不包含明文密码；证明先准备、配置最后提交，失败证明不会使旧随机配置跳过下一次设置。旧会话通过更新 JWT 签名密钥失效。

用户 ZIP 顶层为常用入口，内部代码/运行时/框架放在“程序文件”，data 保持在原根目录。旧包补丁仅包含启动器、窗口和说明，不含 data、框架或依赖；同时兼容旧布局和新布局，不迁移既有数据。停止入口发送仅本实例接受的本地停止请求，由启动器正常中断退出，不按进程名强杀。没有自动桌面快捷方式或开机项。

构建：按 `packaging/artifacts.lock.json` 下载指定官方文件；校验哈希；解压 AstrBot 源码与 uv；保存 uv 的 MIT、Apache 许可证到依赖目录 `uv-licenses`；运行 `python packaging/build.py --deps <依赖目录>`。构建器只收集指定项目目录，不读取开发机的运行数据或 Git 凭据。所有用户文件和完整性清单位于 `dist`。测试运行会修改 `data`，不可重新把已配置、已运行的目录打包；分发必须重新构建。

采用一键引导而非完整离线依赖包的原因：框架引入 149 个传递依赖、多个大型二进制库；全部捆绑会明显增大下载，并扩大第三方二进制许可证/源代码履约范围。本整合包包含运行时、固定原版 AstrBot 源码、同版本 WebUI、uv 和插件；其余依赖由用户首次启动时从官方分发渠道按精确版本和哈希安装。后续启动不重新安装成功的依赖，联网机器人功能仍依赖 QQ 和 DeepSeek。
